# Паспорта блоков отчёта

Паспорт отвечает на вопрос «откуда это число и кто за него отвечает» для каждого блока отчёта:
зачем блок, из чего собран, по какой формуле, кто владелец, какие контроли его держат и какие строки
реестра чисел (`registry.csv`) в нём показаны. Паспорта лежат в `passports/` — по файлу YAML на блок.

## Как паспорт связан с отчётом и реестром

- **Блок → паспорт.** В HTML каждый блок обёрнут в `<section data-block="…">`, значение атрибута —
  `id` паспорта. Блок книги Excel — лист, справочный блок — файл `registry.csv`.
- **Паспорт → строки реестра.** Правила `rows` отбирают строки по ключу (показатель, мера, период).
  Период записан символом, поэтому паспорт годится для любого выпуска: `month` — отчётный месяц,
  `month_ly` — тот же месяц прошлого года, `ytd` и `ytd_ly` — нарастающие итоги, `month_vs_ly`
  и `ytd_vs_ly` — сравнения, `months` — все месяцы реестра. `'*'` в показателе — все строки P&L.
- **Отбор по значению.** Если блок показывает не все строки паспорта (отклонения — только выше порога),
  у паспорта стоит `filter: true`, а правило отбора описано в `selection`.
- **Блок только при перевыпуске.** `only_on: reissue` — в обычном выпуске блока нет, и паспорт тогда
  не проверяется; при перевыпуске блок и строки обязательны, как у остальных.
- **Где число стоит.** Колонка `shown_in` реестра заполняется по готовым файлам выпуска (`html`, `chart`,
  `xlsx`, `registry`) и должна сходиться с паспортами.

## Что проверяет тест

`tests/test_passports.py`:

1. у каждого блока HTML и каждого листа книги с числами есть паспорт, у каждого паспорта — блок;
2. каждое число HTML стоит внутри блока с паспортом;
3. паспорт без строк реестра — ошибка;
4. каждая строка реестра входит хотя бы в один паспорт;
5. блок выводит только строки своего паспорта, а без `filter` — ровно их;
6. лист «P&L» книги совпадает с паспортом по строкам и месяцам;
7. строки справочного паспорта в отчёт не выведены — показанная строка должна жить в паспорте своего блока;
8. `shown_in` совпадает с фактом: `html` — число с `data-r` в отчёте, `chart` — ровно строки паспорта графика,
   `xlsx` — строки листа «P&L» и листа «Изменения»; строка «только в реестре» — справочная или кандидат
   блока с отбором;
9. лист «Изменения» показывает те же числа, что строки реестра по id.

Проверки 1–5 и 8 идут на обоих выпусках: эталонном и перевыпуске из `data/reissue/` против него.

Новый блок в отчёте без паспорта или новая мера в реестре без паспорта роняют тест — это и есть
контроль: число не попадёт наверх, пока не описано, откуда оно и кто за него отвечает.

## Поля паспорта

| Поле | Что |
|---|---|
| `id` | идентификатор, совпадает с именем файла и с `data-block` |
| `title` | название блока для читателя |
| `where`, `marker` | где блок: `html` — `data-block`, `xlsx` — имя листа, `registry` — файл реестра |
| `purpose` | зачем блок руководителю |
| `source` | из чего собран |
| `formula` | как считаются числа; полная методика — [methodology.md](methodology.md) |
| `owner` | владелец — роль, не имя |
| `controls` | контроли, которые держат блок |
| `selection`, `filter` | правило отбора строк словами; `filter: true` — блок показывает часть строк |
| `only_on` | необязательное: `reissue` — блок есть только при перевыпуске |
| `rows` | правила отбора строк реестра: `indicator`, `measure`, `period` |
