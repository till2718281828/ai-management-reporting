# Методика показателей

Документ — договорённость между конвейером (`pipeline/`) и независимой проверкой (`verifier/`).
Проверка не читает код конвейера: она считает всё заново по этим правилам и сверяет с выпуском.

## Исходники

| Файл | Что |
|---|---|
| `data/journal.csv` | проводки: дата, Дт, Кт, сумма в рублях с копейками, статья затрат |
| `data/accounts.csv` | план счетов; `type = pl` — счета финансового результата (20, 26, 44, 90.*, 91.*, 99) |
| `data/mapping.csv` | правило разноски ноги проводки по статье управленческого P&L: счёт + сторона (D/C) + статья затрат → статья; `тех` — закрытие счетов |
| `data/commentary.csv` | причины отклонений — пишет экономист |

**Канонический хэш** исходника: таблица читается целиком как текст, колонки сортируются по имени,
пишется CSV с переводом строки LF без индекса, от UTF-8 байтов берётся SHA-256. Хэш выпуска —
в `output/manifest.json`.

## Знак

Каждая проводка даёт две ноги: дебетовую со знаком минус и кредитовую со знаком плюс.
Доходы положительны, расходы отрицательны.

## Управленческий P&L

Статья месяца — сумма ног по счетам `pl`, которым маппинг назначил эту статью (ноги `тех` не входят).
Промежуточный итог — сумма всех статей выше него.

| № | Строка | Вид |
|---|---|---|
| 1 | Выручка | статья |
| 2 | Материалы | статья |
| 3 | Персонал производства | статья |
| 4 | Энергия | статья |
| 5 | Ремонты | статья |
| 6 | Прочие производственные | статья |
| 7 | Валовая прибыль | итог |
| 8 | Коммерческие расходы | статья |
| 9 | Управленческие расходы | статья |
| 10 | EBITDA | итог |
| 11 | Амортизация | статья |
| 12 | Прибыль от продаж | итог |
| 13 | Проценты | статья |
| 14 | Прочие доходы и расходы | статья |
| 15 | Прибыль до налога | итог |
| 16 | Налог на прибыль | статья |
| 17 | Чистая прибыль | итог |

**Контроль с бухгалтерией:** чистая прибыль месяца = сумма всех ног по счёту 99 за месяц.

## Периоды

Отчётный месяц — последний месяц в проводках. Сравнение — с тем же месяцем прошлого года.
Нарастающий итог `NМГГГГ` — месяцы с января по отчётный; база — те же месяцы прошлого года.

## Меры реестра (`output/registry.csv`)

| Мера | Формула | Единица |
|---|---|---|
| значение | сумма строки за месяц или нарастающий итог | ₽, 2 знака |
| изменение | факт − база | ₽, 2 знака |
| изменение % | (факт − база) / \|база\| × 100; нет числа при нулевой базе | %, 1 знак |
| рентабельность % | строка / выручка × 100 (валовая прибыль, EBITDA, прибыль от продаж, чистая прибыль) | %, 1 знак |
| отклонение сверх роста выручки | факт − база × (выручка факта / выручка базы), для статей 2–6, 8, 9, 11, 13, 14 | ₽, 2 знака |

Изменение % считается к модулю базы, поэтому минус всегда значит «хуже для прибыли»: расходы выросли
или доход упал. Отклонение сверх роста выручки отрицательно, когда статья расходов выросла быстрее
выручки. Для постоянных и финансовых статей (амортизация, проценты, разовые прочие) сравнение
с пропорцией выручки условно: оно показывает, сколько статья «съела» сверх нормального масштаба.

Реестры сверяются между собой по ключу (показатель, мера, период), не по `id`.

## Отображение в отчёте

Суммы — в млн ₽ с одним знаком, проценты — с одним знаком; округление половина вверх. Пробел —
разделитель тысяч, запятая — десятичный знак, «−» — минус. Каждое число HTML выводится как
`<span data-r="<id>" data-f="<формат>">`; формат — `mln` или `pct` с флагами через `|`:
`+` — плюс у положительных, `abs` — модуль, `neg` — сменить знак (флаги применяются в порядке neg, abs).

**Форматы**, допустимые для чисел отчёта (статьи расходов — строки 2–6, 8, 9, 11, 13, 14):

| Мера | Формат |
|---|---|
| значение | `mln`; у статей расходов также `mln\|abs` |
| изменение | `mln\|+` |
| изменение % | `pct\|+`; у статей расходов также `pct\|neg\|+` (рост расходов — с плюсом); у выручки `pct\|abs` |
| рентабельность % | `pct` |
| отклонение сверх роста выручки | `mln\|abs` (знак передаёт слово «хуже» / «лучше») |

Проверка сверяет число с пересчётом по его ключу (показатель, мера, период) и формат — с этой
таблицей. Подходит ли ключ месту в отчёте (колонке, фразе), автоматическая проверка не решает —
это пункт чек-листа приёмки.
